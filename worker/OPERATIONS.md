# Live Activities Worker release safety

Production is `cellblock-live-activities`; the separate `cellblock-proxy` is not a rollback target. The deployable source is this directory and `wrangler.live-activities.toml`; never deploy the retired root `src/` layout. CI runs tests including local workerd/SQLite and a production-config packaging dry run without credentials or deployment. It does not establish live parity or validate remote resources, KV consistency, APNs, Ford or device delivery.

## Before any release

1. Fetch `origin/main`, ensure a clean checkout at the exact reviewed main commit, and confirm checks pass for that SHA. Run `npm ci`, `npm test`, and `npx --no-install wrangler deploy -c wrangler.live-activities.toml --dry-run --outdir <private-scratch>`. Preserve the bundle's SHA-256 and Wrangler version; verify dependency audit findings.
2. Run `npx --no-install wrangler deployments status -c wrangler.live-activities.toml` and `npx --no-install wrangler versions view <active-version> -c wrangler.live-activities.toml`. Record the active version, traffic percentage, compatibility, binding identities and secret *names*, never values. Independently compare the live script downloaded through Cloudflare's content/v2 API against the dry-run bundle for the current production source, and verify config, routes and cron separately. Do not deploy when production drift is unexplained or when main predates live code. Recheck immediately before release.
3. Review remote secrets, KV, Durable Objects, variables, cron and routes against the candidate; a dry run is not proof of their state. Coordinate any migrations and ensure rollback is compatible. Never create production resources as a side effect of a test. No secrets in git, CI logs, version messages, or shell arguments.
4. Only after explicit release approval, use the pinned local Wrangler from this directory: `npx --no-install wrangler deploy -c wrangler.live-activities.toml --message "git <full-reviewed-commit>"`. The message is an operator-supplied claim, not cryptographic provenance: record commit, clean-tree state, dependency lock, build digest, operator, time, previous and new version IDs in the operations journal and independently compare uploaded bytes/config. Do not automate production deploy from untrusted pull requests.
5. Read back deployment status and version metadata; compare uploaded bundle bytes, bindings, cron and routes; probe unauthenticated enrollment/test (401) and an unknown path (404). These probes do not verify authenticated delivery. Watch existing logs and application errors; investigate Ford, APNs and real device delivery separately.

## Rollback

Rollback is a production change, not a test. Determine a previously verified version with compatible existing bindings and DO class lifecycle, and obtain approval; for example, `npx --no-install wrangler rollback <verified-version-id> -c wrangler.live-activities.toml --message "<incident reference>"`. Read back status and versions, check routes/cron and repeat safe probes. Rollback changes the deployed version at 100%; it does not roll back KV or Durable Object data. Cloudflare restricts rollback to the 100 most recent published versions and may reject it after DO class lifecycle changes or resource deletion. Never assume an older version is safe merely because it exists; it may be the retired D1-era build. See https://developers.cloudflare.com/workers/versions-and-deployments/rollbacks/.
